# 普通人可接力的资料源与传播流程

更新：2026-10-09。以免费和手机操作为主；私有库先整理、更频繁更新，公有库审核后批次发布。这里收敛的是日常操作数量，原有84项候选路线保留。

## 普通参与者只做一轮四步

1. **拿到一份**：从已经手机验收的国内入口下载公开资料包，不要求注册GitHub。暂未建立国内网盘入口，当前可从GitHub发行取得后，由维护者手动上传网盘。
2. **保存一份**：将ZIP另存到手机“文件/下载”目录。解压看“先读我.txt”、CSV、图片或播放版视频；不把网盘收藏或聊天记录当成自己的副本。
3. **转交一份**：在主题相关的讨论中手动分享短介绍、图文或小包；保留项目名、资料编号、版本、出处、作者、许可和更正入口。接收者应实际另存文件。评论区优先有用内容，不批量灌水。
4. **回报一项**：告诉维护者“能否打开、能否无会员下载、是否需要客户端、文件是否完整”。没有技术能力也可做这一项。发现错误走更正入口；不要自行公开投稿人身份。

每一份公开包都应有可复制的JSON数据源、可阅读CSV、署名许可、校验表与版本。网站是展示层；包是接力单位。一个网盘链接不算完成保存，两条同账号链接也不等于两份独立备份。

## 公私两库各自负责什么

- **私有整理库**：稳定资料编号、待公开字段、来源索引、pending/approved/withdrawn状态、内容审核摘要。可按每次收件或整理完成更新；时间由维护者记录，不设无人值守自动发布。
- **公有项目库**：网站代码、审核后的目录、公开媒体索引、复制工具、文档和发行包。建议起步每周一个公开版本；急需更正可及时发布，不必等整周。
- **原件保管区**：手机/电脑原件与独立加密备份。真实回执、身份、联系方式、授权文件和视频原件不随Git仓库提交；私有GitHub是访问受限的协作服务，并非端到端加密的证据保险库。

**同步单位是审核导出的文件，不是把私有仓库改成公开、整库Fork或合并私有Git历史。** 公开库被复制时应只带公开信息。独立参与者可仅复制公有库；他们无法也不应取得原维护者的私有原件。若共同维护私有索引，需要明确成员权限。

当前原始私人资料库仍在维护者本地，没有上传。新增私有库起步数据来自已经公开的1251条来源记录；原有“待核对”状态保持。这不表示把1251条都认定成事实，更不表示已经把完整私人库迁移至GitHub。

现已建立[私有整理库](https://github.com/linyoulinhai/jiewangyin-observer-private)，与[公有项目库](https://github.com/linyoulinhai/jiewangyin-observer)分开。私有链接仅拥有权限的成员能查看，普通读者看到404属于权限限制，不是公开下载入口。当前私有库只含已公开基线和空私人字段，未上传原始私人资料、真实投稿或真实媒体；没有自动同步或定时任务。

## 已提供的本地程序

`scripts/release-data.py`仅使用Python标准库，无上传、登录、爬取或自动宣传功能。新克隆本仓库即可执行；原有`dist/tools/build-local-library.py.txt`依赖旧私人工作区，继续保留用于检查旧转换过程。

初始化**新私有工作目录**，只接受明确认定为已公开的目录：

```sh
python3 scripts/release-data.py init \
  --from-public dist/source-catalog.json \
  --destination ../新的私有整理库 \
  --date 2026-10-09 --accept-existing-public
```

不要用此命令把新收集的未审查数据冒充既有公开基线。`records.json`每条记录包含`public`、`media`、`private`和`review`。新条目设为`pending`，私人资料尽量只记录不含身份的内部编号。`public`只允许现有机构目录字段；精确地址、联系方式、原件路径等未知字段会导致导出失败。

人工核对某条资料的**公开范围、正文和媒体授权**之后，执行以下命令记录决定；命令本身不判断事实，也不替代授权：

```sh
python3 scripts/release-data.py approve \
  --source ../新的私有整理库/records.json \
  --id INST-0001 --reviewer 维护者内部代号 --date 2026-10-10
```

审核散列绑定`public`和`media`，内容变化必须再次审核。withdrawn/pending不导出。经历正文仍走已有独立审核，不混进机构目录字段。

生成新公开版到**公有仓库外的新目录**：

```sh
python3 scripts/release-data.py export \
  --source ../新的私有整理库/records.json \
  --output ../公开资料版-2026-10-10 \
  --version 2026-10-10
python3 scripts/release-data.py verify ../公开资料版-2026-10-10
```

有上一版时加`--previous ../公开资料版-2026-10-09`；有获准公开的媒体时加`--media-root ../公开媒体副本 --volume-mb 200`。默认200MiB是可修改的分包目标，不是网盘限额承诺。单个文件超过目标会中止，需先制成更小的公开播放版或使用原有字节分包工具；字节分包不能单段播放，禁止当成可播放切片。

公开输出包括：

- `source-catalog.json/csv/js`：完整公开快照，稳定ID保持，可供下一位维护者重新初始化自己的私有索引；JSON是无损源，CSV为手机表格阅读作公式安全处理。
- `media-index.json`：公开媒体ID、机构ID、大小、散列、许可、公开镜像和分包位置。**没有媒体时为空，不把链接记录写成已取得原件。**
- `media/`与`packages/media-*.zip`：已授权公开副本及小分包；原件和公开副本的存储根目录须分开。分包内仅媒体，许可和索引在根目录，转交时一起保留。
- `changes.json`：与指定上一版比较的新增、修改、移除ID。它是变化清单，当前版本JSON仍是完整快照；尚未实现自动增量下载媒体。
- 提供者、许可证、散列清单与“先读我”。同样输入和版本产生相同文件；发布时间、私有更新时间、审核者与私人字段不导出。

验证命令发现缺文件、多余文件或散列不一致就失败。散列只能证明文件一致，不能单独证明来源真实、审核决定正确或作者身份。公开版中的自由文字、图片内容仍必须人工检查；字段白名单不能自动识别所有个人信息。

## 接进现有网站和发行

1. 验证新导出目录，人工复看公开字段、图片视频和更正记录。
2. 将三个`source-catalog`文件替换公有库`dist/`内对应文件。媒体索引与小包先作为发行附件、网盘附件提供；**当前网站还没有读取新媒体索引的UI适配，不自动宣称已展示新视频。**
3. 如修改根目录致谢/多平台指南，同步到`dist/ACKNOWLEDGEMENTS.txt`、`dist/MULTIPLATFORM-GUIDE.txt`。运行`python3 scripts/package-public.py`重打网站公开包，再运行项目检查。
4. 提交到公有库、生成新的公开版本；手机传播者收到公开版即可，不需要私有库权限。原站部署仍走原托管流程，GitHub推送不会自动替换原站。
5. 网盘与社交账号由你操作；选一个国内目录入口、一个公开下载入口和一位独立副本维护者完成真机验收，再补第二家存储。跨境备用放独立清单。

## 视频路径改成三种用途

推荐原件保管区`originals/机构编号/年月/内部媒体编号/`，公开副本区`public-media/机构编号/公开媒体编号/`，发行区`公开版本/packages/`。这只是推荐目录，不移动或删除你已有文件。原件可单独加密保存到本地盘和用户自选网盘；加密密钥另存，不能和公开包一起分享。

**原件**用于私人保存和核对，**播放版**用于B站/抖音/视频号等展示，**可转交版**用于获准再分发的下载。只允许播放的素材不能直接进入可转交包；视频里的人脸、声音、姓名、背景信息与授权范围要一起检查。平台转码视频和“我的收藏”不充当原件备份。

媒体条目需要`id/title/source_url/rights/redistribution/privacy_reviewed/sha256/bytes/storage_relative/mirrors`。程序要求`redistribution="allowed"`与`privacy_reviewed=true`；`storage_relative`只定位公开副本，导出后不保留内部路径。公开镜像必须不带账号口令或临时签名令牌。授权凭证另存私人区。

GitHub普通Git不适合不断加入视频原件：官方对大文件和仓库大小有约束。Releases可以作为经过授权的小媒体包备用，但不当作全国视频的唯一长期存储。官方限制见[大文件说明](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)和[发行附件说明](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)。LFS保留在原清单，现阶段没有开通付费额度。

## 更正、撤回与接力维护

私有索引将相关条目设为withdrawn并记录内部原因；导出新版本，公开变化清单只出现已公开的移除ID，不泄露未公开线索。新资料已存在但还未审查时保持pending。变动一个原已公开条目会要求重审；未重审会中止本次导出，避免悄悄发布改动。

公开传播者拿到新版本后更新自己的文件、网盘目录和说明，向接收过旧包的维护者发更正提醒。已被下载的旧文件无法保证收回；处理隐私等必要更正时，应同时清理自己可控制的旧发行附件和镜像，保留不泄露内容的更正记录，而非机械保留有问题的旧版。

## 参考案例及实际借鉴范围

- [Tella文档](https://tella.app/docs/)：借鉴手机收集、独立服务器连接和近距离共享分层。只是研究，未集成Tella、未验证相关境外连接国内可达。
- [ProofMode Preserve](https://proofmode.org/preserve)：借鉴“媒体＋元数据＋独立副本”的包结构。其IPFS/Filecoin路线保留为备用，不复制其桌面前置条件到普通手机用户入口；散列不等于本站已实现签名认证。
- [LocalSend](https://localsend.org/)：可用于手机/电脑在同一局域网交接公开包；不是远程网盘，不替代长期保存。下载与真机交接仍由用户实测。
